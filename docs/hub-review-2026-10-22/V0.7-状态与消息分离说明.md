2026-10-22。用户明确提出：输入框上部增加只展示 Graph 状态的看板，形态接近 Plan；具体步骤和操作由消息流卡片承载。

用户随后确认将该方案合并到原型图评审稿。V0.7 现为当前协作过程评审基线；本次确认不等于正式产品实施或完整运行验收。见[主评审稿](README.md)。

## 本轮修改

| 层次                    | 展示内容                                                         | 交互边界                                                   |
| ----------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| 输入框上方的 Graph 看板 | 工作名称、整体状态、已完成阶段数、阶段路径与各阶段状态           | 只读；不放业务按钮、成果入口、节点详情或专家内部 Plan 步骤 |
| Hub 消息流              | 范围确认、专家问题、审核进展、版本成果、修改意见、执行与暂停回执 | 在对应消息卡中回复、看成果、确认、退回、暂停及恢复         |
| 既有专业线程            | 原讨论与修改记录                                                 | 保留原线程入口；本轮没有新增专家内部 Plan 步骤看板         |

看板位于独立于消息滚动区的输入组件上方，演示采用固定 96px 高度。阶段变化不会展开看板或改变消息区高度。96px 不是正式产品尺寸约束；实现时应适配用户字号及实际宿主布局。Graph 展示跨角色协作阶段，Plan 展示单个 Agent 的执行步骤；相近形态不意味着二者共享业务完成语义。

协作事件按顺序追加到消息流。已处理卡片保留原问题、范围、版本与处理回执，不再提供旧的放行或执行按钮；历史成果仍可按版本查看。普通讨论与定向回复按发生顺序保留。

停在消息底部时跟随追加内容；向上阅读后保持位置，用户可点击消息区中的「查看最新消息」自行返回。该导航不属于状态看板。草稿与回复对象规则继续沿用 V0.5。

## 验证记录

- 顺序体验：范围确认 → 定向回复 → 审核 → 用户放行 → 开发 → 暂停／恢复。
- 退回旧版本后新增修订卡，新版本重新审核确认；原成果卡保留退回记录与固定版本入口。
- 看板中业务按钮、链接和输入控件数量为 0；仅存在一张当前操作卡，历史卡中没有旧业务执行按钮。
- 仅方案范围显示 3 个阶段，确认后为 3/3 完成，不出现开发阶段。
- 1025×823：保持历史顶部阅读位置时切换审核状态，消息滚动位置仍为 0，看板位置保持约 520px；未发送草稿仍在。
- 底部跟随：追加阶段后与消息底部间距为 0；用户脱离底部后不强制回到底部。
- 600×800：页面与看板无横向溢出。
- 1280×720：从较高窗口缩小且此前停留底部时继续跟随，放行按钮底部约 351px，消息区底部约 413px，操作未被看板遮住。
- 独立脚本语法、文档相对链接及来源副本检查通过。

这是可点击的本地演示，未修改正式产品、未接模型或真实调度。看板和消息卡展示同一份模拟状态，不证明真实事件同步、长期持久化、多计划或辅助技术完整可用。
