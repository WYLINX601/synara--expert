# Expert Skill 主动进化产品方案

日期：2026-10-28；执行更新：2026-10-29。状态：已实现并完成本轮隔离预览验收，未安装日用。本轮“主动进化”指用户主动发起提炼；不开放会话结束自动触发、定时复盘或自动采用。实际完成与未验收范围见[实现验收](./expert-skill-evolution-acceptance-2026-10-29.md)。

配套：[研发方案](./expert-skill-evolution-technical-plan-2026-10-28.md)、[实施计划](./expert-skill-evolution-implementation-plan-2026-10-28.md)。

## 1. 本轮目标与完成标准

用户在一个 Expert 的页面选择它的工作记录，主动提炼可复用方法，查看候选与差异后采用。采用依 Skill 策略更新共享版本或专家专用版本；允许无需提炼；当前运行及恢复保留旧装配，下一次独立运行使用新版本。

以专家为经验归集与贡献归属主体，以 Skill 为能力产物；专家不产生 Memory。提炼来源、审批、版本和派生记录是审计数据，不自动注入后续普通会话。

本轮完成标准：一条真实专家工作记录可以产生可追溯候选；用户能正确采用或拒绝；另一次运行能装配采用后的版本；原共享内容、其他专家和当前运行的变化符合选定策略。

## 2. 保守范围

| 本轮包含                                             | 后续范围                                 |
| ---------------------------------------------------- | ---------------------------------------- |
| 用户点击提炼；选择同一专家的一到多段已结束工作记录   | 会话结束、纠错信号、空闲或定时自动触发   |
| 从来源生成候选，或返回无需提炼／证据不足             | 模型直接修改正式 Skill、无人确认自动采用 |
| 受保护、共享进化、独立进化三种策略                   | 自动合并技能、自动归档、自动改变策略     |
| 首次派生、专用版本更新、共享版本更新、新建专用 Skill | 模型权重训练、系统提示和工具定义的进化   |
| 候选差异、采用、拒绝、失败恢复、恢复旧内容           | 公开市场、远程发布、星图分享码           |
| Expert 内的时间环星图、版本记录和来源查看            | 新建独立学习中心或全量重做专家页面       |
| 用户将专用 Skill 开放给其他专家，并明确其策略        | 专家自行扩大共享范围或跨专家读取未选材料 |

本期所有模型产物先停在候选，用户“采用”完成一次明确写入。允许进化仍表示长期策略许可；本期的预览与采用是主动操作流程，不增加第二轮审批，也不提前实现自动采用。

## 4. Skill 策略与权限

| 策略     | 提炼结果                         | 正式写入及影响                                                                         |
| -------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| 受保护   | 可以提出更新或派生建议           | 用户查看目标、差异和影响范围后认可本次操作；不自动解除保护，也不以复制绕过认可         |
| 共享进化 | 只沉淀适用于其他使用者的通用方法 | 同一 Skill 产生新版本；其引用专家在下一次独立运行使用更新                              |
| 独立进化 | 首次创建当前专家的完整副本       | 原版保留；替换当前专家对应绑定并保持原启用／启动方式；后续更新该专用 Skill，不反复复制 |

既有和新导入 Skill 缺省为受保护。新建无来源方法默认专家专用、受保护，用户可另行设置。已存在、且属于当前专家的独立副本优先更新；其他专家的专用 Skill 不作为候选目标。

共享进化需判断通用性：专业角色的特定流程、具体项目事实和用户个人资料不写入共享方法。只有专家专属经验时，不悄悄改变策略；返回原因，用户可以改用经确认的独立方式。专家只能修改内容，不能自行改变策略、归属、共享范围或目标专家。

“开放给其他专家”是用户操作：展示完整文件范围与策略后，将当前专用 Skill 改为共享可用，保留原始派生与贡献来源，不覆盖其上游原版、不自动绑定其他专家。共享后，后续写入遵守用户选定的新策略。

## 5. 主流程与 UI

### 5.1 入口

- 专家详情的任务历史：选择一个或多个来源，再点“提炼 Skill”。
- 专家详情的进化页签：点“提炼 Skill”后选择来源。
- 两个入口打开同一流程，不创建两套提炼状态；不在普通聊天输入区新增强制步骤。

专家已归档时保留只读记录，不能发起或采用。原有专家编辑草稿需要先按现有保存／放弃／取消规则处理；提炼使用已保存配置，不隐式保存其他草稿。

### 5.2 选择来源与生成

提炼面板显示专家、可选工作记录、实际运行及来源版本、目标 Skill、可选提炼重点、实际 Provider／模型与影响范围。沿用现有运行选择组件及用户配置，不创建管理 Agent 或默认切换模型。

首期一次至多选择 5 段已结束工作片段；每段固定消息截止位置。只选择当前专家实际参与的材料；专家团按实际贡献身份归属，不把团队总结自动作为所有成员经验。运行中、取消中、身份无法确认或材料不可读的片段不能直接作为可靠成果；已结束的有效片段可以单独选择，无需关闭整段长会话。

材料超出可用上下文时提示缩小范围，不静默截断，也不自动读取所有历史、项目目录或外部链接。来源的“回合结束”不表示成果已经验收；候选必须指出纠正或有效方法的具体依据。

点击“开始提炼”才创建一次模型任务。显示排队、分析中、等待原生权限、候选就绪、无需提炼、证据不足、失败或取消状态；关闭面板不等于取消。提供“查看提炼任务”和明确的取消入口。

### 5.3 查看结果与采用

| 结果         | 用户看到什么                                       | 后续行为                                               |
| ------------ | -------------------------------------------------- | ------------------------------------------------------ |
| 有可复用改进 | 名称、目标、原因、来源、文件差异、策略与影响的专家 | 用户采用单条候选，或拒绝；候选可先编辑，编辑后重新校验 |
| 无需提炼     | 已覆盖、无新增方法、只有一次性信息等简短原因       | 正常结束；不创建 Skill、版本或进化节点                 |
| 证据不足     | 方法尚未证实或材料缺失                             | 保留本次记录；用户补充材料后主动重试                   |
| 分析失败     | 实际错误、任务链接、可重试操作                     | 失败不显示为无需提炼，不改正式 Skill                   |

一次最多生成 3 条候选，逐条采用；不做跨候选一键原子批量采用。用户采用前能核对完整文件列表、支持文件、删除项、共享影响和来源链接；不是只给模型总结。

受保护候选的采用按钮明确为“认可并采用本次改动”；共享候选为“采用到共享版本”；独立候选为“创建专用副本并采用”或“更新专用版本”。点击后不再弹重复的泛化确认。

原目标、策略或专家绑定已改变时显示版本冲突，保留候选并允许基于最新状态重新提炼。禁止后写覆盖。不在用户已审过的差异上自动合并另一份内容后直接提交。

### 5.4 部分完成与恢复

独立副本保存后、专家绑定前失败：明确显示“专用 Skill 已保存，尚未绑定”，提供继续绑定和查看 Skill；重试复用同一副本，不重复创建。只有绑定完成才标为已采用并记录能力变化。

恢复旧内容需要预览旧内容与当前内容的差异，并确认受影响专家；恢复会生成一个新的修订，不改写历史，不修改当前运行。首次独立采用的撤销涉及恢复原绑定时，必须显示具体绑定变化；不自动删除已被引用的副本。

## 6. 星图与版本记录

沿用 Hermes 的时间环布局、平移缩放、时间轴播放／暂停、节点选择和详情。专家通过页面标题与数据范围体现，不再设置一个巨大的专家中心节点。

- 一个 Skill 身份一个节点；版本放在节点详情和进化记录中，不因每次修改制造新节点。
- 首次派生画有方向的来源关系；明确关联可另行表示，不能把相似度连线当作血缘。
- 已绑定／已装配的共享来源可作为基线节点，不计为新学会能力；没有真实调用证据时不写“已使用”，节点大小固定，不编造能力分数。
- 时间轴基于实际采用事件；旧数据缺少创建时间时标为“基线／时间未知”，不从更新时间猜学习时间。
- 时间回溯展示当时已记录的节点和版本；无历史证据的时期不补造过去事件。
- 节点显示共享／专用、策略、版本、派生来源与贡献专家；点击查看现有技能详情及选定版本差异。
- 无需提炼、被拒绝、失败及候选未采用只在记录中出现，不点亮新能力。
- 首期不提供星图分享码，不把图分享与 Skill 开放混为一项操作。

## 7. 不变的运行规则

Skill 内容或绑定更新从下一次独立运行生效；当前运行、审批等待、自动续接及恢复使用原装配。专家角色和 MCP 配置继续遵守原快照规则。内容保存、装配成功、模型实际采用与业务效果验证是不同状态，不互相代替。

## 8. 产品验收

1. 两个入口使用同一流程，只读取所选专家、所选材料，不影响普通聊天。
2. 用户开始前不运行模型，候选采用前不改变正式 Skill 或绑定；拒绝和无需提炼不写正式 Skill、修订或绑定，保留必要审计记录。
3. 受保护操作需要本次明确认可；策略改变不会由模型或来源内容授权。
4. 共享更新只写通用内容，显示影响专家，保留旧版本；无效差异不增加修订。
5. 独立进化首次派生一次，保留原版和绑定方式；后续更新同一专用身份。
6. 重复提交、断线和重启不重复启动、重复创建或重复绑定；部分完成如实呈现。
7. 当前／恢复／自动续接装配不变，下一次独立运行可验证装配新版本。
8. 星图、记录、版本和来源一致，键盘、缩放、字体、减少动画、窄屏及真实父布局可用。
9. 专家不生成 Memory；提炼任务不递归作为新经验来源，不自动开放或执行生成脚本。
10. 真实模型验证与平台验证按实际结果记录；本方案和原型不作为完成证明。
