# 案例：Synara 禅模式从重画改为真实挂载

## 输入与确认边界

- 原型目录：`apps/web/prototypes/zen-companion/`，源码输入 `61264859d`，另有未提交的隔离原型代码。
- 用户参考：透明桌面上的白色圆角输入表面，底部原生的附件、权限、模型、语音和发送控件。
- 用户纠正：能力是**整体协作陪伴**；Obsidian 写作只是一个使用场景。
- 用户明确反馈：早先重绘原型保真度不足、完整流程未建立、未充分复用现有组件。
- 03 版恢复真实生产界面后，用户确认“已经对齐”，才授权右下角气泡和往返优化。此确认不等于优化版或正式产品验收。

## 有效接法

`main.tsx（评审/拟议窗口外壳） → 同一个 app.html iframe → baselineApp.tsx → getRouter / RouterProvider → 原父布局 / StoreProvider / QueryClient / ZenModeProvider / ChatView`。

- 应用内部输入、消息、抽屉、菜单、审批、问题与错误均来自生产组件；不复制 ChatView。
- `baselineApp.css` 导入生产 `index.css`，并为独立 Vite 根补齐生产源码 Tailwind 扫描。
- `baselineFixture.ts` 复用正式浏览器套件的 MSW / Effect RPC 测试边界；模块创建连接前完成拦截。使用合成协作任务，不读写用户项目。
- `previewBridge.ts` 只模拟原生窗口可验证的尺寸/模式通知；未知能力明确不可用。
- 主窗口和禅模式保留同一个 iframe / 路由树，避免草稿和会话复制。

这些文件是该仓库案例，不是可拷贝到任何项目的通用模板。新项目优先找到自己的真实入口和测试 harness。

## 暴露过的失败与修正

### HF-CASE-01：基础组件复用不足以保证整体保真

以前的自绘面板和局部组件包装脱离完整生产布局。修正为挂载真实路由树；移除自己的旧包装，不用第二套样式“补得像”。

### HF-CASE-02：独立 Vite 根没有扫描生产 Tailwind 类

组件引用正确也可能显示失真。补齐生产源码扫描后检查实际像素；不改生产样式来补构建配置错误。

### HF-CASE-03：Enter 能发送，点击原发送按钮却不提交

iframe sandbox 缺少 `allow-forms`，导致原生 submit 受阻；Enter 经过另一条编辑器处理路径，因此不能替代按钮验收。修正隔离层权限并重新实际点击发送；不改生产 handler 绕过限制。

### HF-CASE-04：状态列表不是完整流程

快照按钮能展示“待审批”，不代表批准、拒绝、取消后的转换已经跑通。后续实际操作原问题/审批控件，记录对应结果；显式区分模拟执行与真实 Provider。

### HF-CASE-05：网页窗口变化不是桌面能力证明

真实组件往返时同一个编辑器和中文草稿保持，说明应用组成连续；不能据此声称跨应用焦点、常驻置顶、系统托盘或多屏成功。桌面原生能力另做产品实现与验证。

### HF-CASE-06：复原准确仍不等于可交付前端

用户进一步明确：交互原型用于提前审核最终前端能力，避免完整开发后返工，不是独立演示稿。真实挂载解决了原貌偏差，但预览专用的交互外壳不能自动算作产品实现。后续优化按 HF-00 核对共享实现与完整能力矩阵；前端应直接沿用，数据和原生边界的模拟仍需明确标注，不能把历史预览追认为已完成集成或用户验收。

### HF-CASE-07：窗口边缘控件不能留给评审外壳

把“收起为气泡”“返回工作台”放在外侧工具条，再说明它代表未来的原生标题栏，会漏掉成品的布局和可达性评审。07 版新增共享 `ZenWindowChrome`，紧凑态位于输入/决策表面上沿，展开态位于窗口右上角；删除外壳的重复操作。预览只提供可选 `collapseToBubble` 宿主接口的可见性模拟，真实桌面没有该能力时不展示无效按钮。前端入口的实现与原生能力的接通必须分开验收。
