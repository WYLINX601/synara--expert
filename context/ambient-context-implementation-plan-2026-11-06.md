# Ambient Context 落地范围与路线

来源：[整合方案分析](chatgpt-conversation://6aeae4d1-eecc-83ea-aae4-871ce7148a46)，最终方案消息 `2c87f8fa-251c-495e-9520-a387e0768006`。本次已读取方案主体；读取接口在 20,000 字符处截断末尾“非目标”，不声称保存完整原文。用户于 2026-11-06 要求实施，并进一步确认本轮先交付 Obsidian 闭环，后续逐阶段推进。

## 已确认边界

- 系统、Obsidian、Browser 是并列来源，可分别启停；应用来源不依赖系统感知。
- Synara 定义有版本的 Context 类型、来源能力、用户类型策略和快照。权限与偏好分开，未知信息不猜测。
- 感知只提供数据，不承担外部应用操作、工具授权或 Harness 生命周期。
- Active 保存各来源最新批次，短期过期，不记录全局历史；显式固定的引用属于当前聊天草稿，发送后的不可变快照随消息保存。
- 不实时注入运行中的 Agent；当前发送、排队、重试和恢复都使用原消息快照。
- 外部正文始终是不可信数据；保持现有 Space/Project Context 与 Provider 适配层的职责。

## 本轮实现与接入

| 项目                     | 所有者与接入                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| 类型与大小限制           | `packages/contracts/src/ambientContext.ts`，七种判别联合类型；正文与选区有单项限制、快照有总限制     |
| 过滤、关联、去重、格式化 | shared 显式 `ambientContext` 子路径；先按策略/权限过滤，再仅依据精确资源身份关联；同质量冲突保留歧义 |
| 来源生命周期             | Electron 主进程 Manager；缺省关闭，串行启停，代次隔离晚返回；断连/关闭清空实时批次                   |
| Obsidian 接入            | 独立 Companion；仅编辑器公开 API，读当前未保存选区与位置；文件名/路径搜索，不索引全文                |
| 本机桥接                 | 仅 IPv4 loopback，随机临时端口与会话配对凭证，单一 Vault 连接；不提供任务执行、文件修改接口          |
| 设置                     | 既有 `_chat.settings` Connectors 区域，复用设置组件；偏好保存在当前桌面应用 userData，凭证不持久化   |
| Composer                 | 既有 `_chat → ChatView`，沿用宿主订阅/快捷键/草稿；显式 Attach、引用 Chips、`@` 文件检索             |
| 消息与恢复               | 原生命令/事件/投影保存 `ambientContext`；工作台扩展迁移增加可空投影列；Provider 公共入口统一格式化   |

Active 是来源最近一次有效状态，保留最多 30 秒，允许切回 Synara 后固定；不据此声称知道操作系统当前前台应用。正文缺省关闭；最小默认类型为应用、资源身份、选区文本与选区位置。首版不提供窗口身份：插件实例 ID 与笔记名称不能证明系统窗口身份。重新启动或改变来源类型后须重新配对。固定引用不因关闭来源被删除；关闭停止新采集，已固定/已发送数据遵循草稿/消息生命周期。

异常处理：未配对拒绝；第二个 Vault 不替换已有连接；过期、乱序和旧代次事件不参与捕获；超量采集清空上一批次并告知用户；无法保存偏好不伪报持久化成功。元数据不授予文件读取权限。插件输出、静态类型和模拟 Provider 测试均不等于真实应用/模型验证。

消息投影的新增列使用现有通用 Workbench 扩展序列 `expert` 的第 14 项；这里的历史 ledger 名称不把环境上下文归入 Expert 业务。冻结的 `context,1` 和上游迁移保持原样。旧服务器缺少 `ambient-context.v1` 能力时，带快照的消息保留在草稿/队列并明确拒绝发送，普通消息不受影响。历史会话重建继续遵守既有摘要预算，无法装入的历史快照须标记省略；完整原快照仍保存在消息中，不用当前应用状态替换。
