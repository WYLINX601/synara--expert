## 2. 目标、保留项与非目标

### 2.1 用户目标

在其他应用工作时，Synara 低打扰常驻；随时打开同一会话，处理输入、回答或审批；可回完整工作台，不重新找聊天、不丢草稿。窗口控制与内容操作分开，但视觉上属于同一个禅模式表面。

### 2.2 必须保留

- 真实 `ChatView`、输入编辑器、模型/权限/附件/语音/发送操作、消息抽屉、待回答与审批组件。
- 右下角停靠，向上/向左展开；显隐不重建聊天树、不复制会话、不停止任务。
- 已有审批响应、回答提交、取消、错误恢复、Provider 能力限制与执行语义。
- 原生主窗口与禅模式互斥、同一已挂载聊天的既有架构；不要默认新建第二个聊天窗口交接状态。
- 主窗口普通聊天、异步问题卡、任务面板与 Hub 审批不因本轮禅模式布局变化而改变。

### 2.3 非目标

不重新设计输入框、不新增作者绑定流程、不增加模型切换规则、不建立第二套任务状态机。SVG 不是实现文件，不把 SVG 作为成品控件嵌进应用。真实宿主接入须分配对应工程任务，不能用网页模拟替代原生交付。

## 3. 最终交互规则（稳定编号）

### ZC-20｜默认全隐藏，Hover 整组显现

- 默认不显示三个图标、中央箭头、胶囊底板或占位标记。
- 在当前表面上沿中央保留稳定、连续的不可见命中区；鼠标进入时三个按钮及容器一起显现，不要求先点一下。
- 显现后从左到右为：**收起为气泡 / 展开或收起对话 / 返回主窗口**。三个独立按钮，不嵌套 button，不将整组点击都绑定到展开。
- 在按钮和组内间隙之间移动时持续显示；鼠标离开整组且没有键盘交互焦点时，整组隐藏。
- Hover 不改变内容布局、输入高度或宿主窗口尺寸；不以增加一行 padding 的方式制造操作区。
- 鼠标点击产生的普通焦点不应让操作组永久常驻。键盘导航进入时可以显现并保持；焦点离开后按 Hover 状态恢复。
- 触发区不可只覆盖尚未显示的图标像素；也不可扩大为整个窗口，导致用户无法点击背景应用。

### ZC-21｜收起对话时的锚点

- 组中心对齐当前输入表面上沿的水平中心。
- 普通输入状态与待回答/待审批状态共用此规则：决策卡替代输入框时，以决策卡上沿为锚点。
- 组为覆盖层，显现前后输入框/卡片底边不动；原模型、权限、语音和发送操作不换位。
- 删除 08 版输入工具栏内和决策标题内的两枚窗口图标，不保留重复入口。

### ZC-22｜展开对话时的锚点

- 整组移到**展开抽屉最上沿中央**，以 SVG 第三态为准；中间箭头朝下，名称为“收起对话”。
- 不是抽屉右上角，不是输入框与抽屉接缝，也不是消息列表中某条消息的顶端。
- 控件应属于抽屉外框覆盖层，不随消息滚动；在空会话、历史会话、状态详情和审批/问答场景中均有稳定锚点。
- 展开后默认仍全隐藏；Hover 当前顶部触发区或键盘访问时整组显示。
- 收起后回到 ZC-21 锚点。任一时刻只有一组有效控件；不要保留旧位置的透明可点击副本。

### ZC-23｜三个按钮的动作与失败处理

| 按钮          | 动作                   | 必须保持/限制                                                          |
| ------------- | ---------------------- | ---------------------------------------------------------------------- |
| 收起为气泡    | 禅面板退回右下角入口   | 任务继续、草稿/会话/抽屉状态保持；不等于取消或批准                     |
| 展开/收起对话 | 只切换历史/详情抽屉    | 不提交输入，不回答问题，不改变任务状态；`aria-expanded` 与真实状态一致 |
| 返回主窗口    | 调用现有退出禅模式路径 | 保留同一会话与草稿；返回禅模式仍使用原入口与真实状态回执               |

操作 pending 时沿用原禁用与错误处理，不重复发请求；失败不能假报已切换、隐藏唯一操作入口或丢草稿。外部通知不得自动显现/展开操作组、夺取焦点或切换窗口形态。按钮隐藏不等于任务停止。

### ZC-18/19｜常驻入口（沿用 08 版）

- 36×36px 圆角方形、10px 圆角、20px 原 Synara 品牌图标；不恢复 48px 圆形。
- 默认位于工作区右下角，普通预览距右/下边 28px，低高度/窄预览 16px；原生以可用工作区避开 Dock/任务栏，不直接贴物理屏幕边缘。
- 单击唤起同一协作会话；右键菜单仅提供“隐藏陪伴入口”，不增加独立“···”按钮。
- 支持键盘 ContextMenu / Shift+F10；Esc 关闭菜单后返回入口焦点。
- 隐藏不同于收起：隐藏后入口也消失，但任务继续；必须有宿主恢复路径。原型的“模拟托盘”仅为评审工具，不能作为最终产品入口。
- 状态提示继续使用静态标记；后台完成不自动打开面板。会话/专家切换不属于本轮新增逻辑。

### ZC-08/10/11/16｜决策状态（沿用已有方向，补足工程验证）

- 待审批用原审批组件替代普通输入表面；普通编辑器保留挂载、隐藏并 inert。批准/拒绝/取消使用真实 handler，草稿不丢失。
- 待回答用原问题卡替代普通输入表面；“其他/自定义输入”为最后一个可输入选项，不再并列显示完整聊天输入框。
- 输入提交、前后题导航、多选确认必须可达；单选自动推进沿用原规则，不能错误套用于多选。
- Enter、Shift+Enter、输入法组合输入与正在提交的禁用行为需验证；多选、无选项、失败重试不能只依赖历史单选样例。
- 决策内容保持有界滚动。当前原型使用固定 20rem 上限避免紧凑窗口尺寸反馈；合并工具组时不能误删此保护。
- 当前 08 版的限高与 `headerActions` 是否存在关联；移除旧标题图标槽时必须保留禅模式滚动约束，并保持非禅模式组件行为不变。

## 4. 状态与转换矩阵

下表是行为契约，不要求创建同名的新 store 字段。既有宿主/Provider/聊天 Store 继续拥有真实状态；Hover/键盘显现仅为局部 UI 状态。

| 起点               | 触发                           | 结果                             | 不得发生                 |
| ------------------ | ------------------------------ | -------------------------------- | ------------------------ |
| 气泡               | 单击                           | 同一禅面板恢复，保持原抽屉状态   | 新开会话、自动换专家     |
| 紧凑面板，指针在外 | 进入上沿触发区                 | 输入/决策卡顶部整组显现          | 只出现箭头、输入框增高   |
| 工具组已显现       | 跨越按钮间隙                   | 持续显示，可分别点击             | 闪退、需要再次找命中区   |
| 工具组已显现       | 移出且无键盘焦点               | 整组隐藏                         | 留底板或残留箭头         |
| 紧凑面板           | 点击中间按钮                   | 抽屉展开，工具组锚点移至抽屉顶端 | 在接缝留下第二组控件     |
| 展开面板           | 滚动消息/决策内容              | 工具组相对所属外框位置稳定       | 随消息滚出窗口           |
| 展开面板           | 点击中间按钮                   | 抽屉收起，锚点返回输入/决策上沿  | 丢草稿、改变阅读跟随意图 |
| 任一禅面板         | 点击收起为气泡                 | 气泡，任务继续                   | 停止、审批自动通过       |
| 任一禅面板         | 点击返回主窗口，再从原入口返回 | 同一会话/草稿/抽屉状态恢复       | 重载应用或复制状态       |
| 气泡               | 右键→隐藏                      | 入口消失，仍可从宿主恢复         | 关闭任务、没有恢复路径   |
| 收起/隐藏          | 收到任务进度/完成/审批         | 更新适当状态提示                 | 擅自唤起、抢焦点         |

## 5. 视觉、可访问性和命中规范

- SVG 修订 02 确认的是三态、整组显隐和锚点迁移。图中工具组约 126×28px 为示意尺寸，尚未通过真实 Hover 手感验收，不把整幅 SVG 的缩放尺寸硬编码进组件。
- 复用现有 `IconButton`、图标、Tooltip、主题和字号 token；适配深浅主题与用户字体大小，不复制 SVG 中简化的模型图标。
- 三个按钮视觉等高；中间始终是展开/收起，左右顺序固定。无支持气泡能力时参见宿主边界，不显示无效按钮。
- 复用 `disclosureMotion.ts`，遵守 reduced-motion；只为显隐使用现有轻量动画，不建立新时间常数，不为动画参与窗口高度测量。
- Tooltip 说清动作，不只依赖“-”或方角图标；语义应为“收起为气泡”“展开/收起对话”“返回主窗口”。保留现有翻译键，新增文本须同步语言资源。
- 键盘 Tab 可进入控制组，显现后焦点可见；Enter/Space 只执行当前按钮。原菜单、编辑器、输入法和 Esc 语义不被全局劫持。
- 隐藏层不能吞掉输入或背景应用点击；原生 `data-zen-hit-surface`/穿透策略要覆盖合法触发区和按钮，并排除不相关透明区域。
- 拖动与按钮命中分开；原窗口拖动能力不得被整组操作替代。不要对包含按钮的区域设置原生 drag 命中。
- 触控无 Hover 的显现策略不是本次确认内容，不声称移动端已设计或验收；若纳入发布范围需另行确认。

## 7. 宿主接口与前后端边界

当前 [ZenModeDesktopMethods](../../../../packages/contracts/src/zenMode.ts) 包含 `enter`、`exit`、`setExpanded`、`setCompactHeight`、`setPointerPassthrough`、状态订阅和可选 `collapseToBubble`。这次交接不虚构新的后端协议。

- 显隐、Hover 与三个按钮的布局属于前端；展开/返回调用现有宿主路径。异步回执失败时保持可恢复状态。
- `collapseToBubble` 当前仅有预览桥接实现；正式宿主缺失时沿用能力判断，不展示点击无效的收起按钮。要交付完整“三按钮＋常驻入口”产品能力，必须完成对应宿主实现。
- 真气泡、系统托盘恢复、可用工作区、跨应用焦点、鼠标穿透、跨屏与全屏需真实桌面验证。不要用浏览器 iframe 的焦点结果冒充跨应用结果。
- 宿主隐藏/恢复入口目前没有在上述接口中完整统一定义；工程师应复核现有桌面能力后补齐，不直接把 `showContextMenuFallback` 和“模拟托盘”搬成产品架构。
- 保持既有单窗口/同一会话原则；需要改变窗口生命周期或进程边界时由工程师与协调员先收敛架构，不在 UI 层偷偷新建第二套会话。
- Host seam 变更同步 [接入清单](../../../../workbench/integration-points.json) 并运行现有边界检查；扫描不是运行时隔离证明。
