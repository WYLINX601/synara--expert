## 案例暴露的产品问题

**本案例支持的判断是：Skill 资源的配置状态，不能单独代表它在某个任务中的可用状态。** 完整的技能包仍可能依赖特定工作目录、项目配置或初始化动作。

由此可以提出一个产品问题：用户为 Expert 选择 Skill 后，怎样知道它是否能够在当前任务中真正开始工作；如果不能，怎样理解原因并继续？这是根据案例提出的讨论切入点，尚未成为用户确认的产品目标。

需要进一步区分以下信息。这里用于分析用户需要知道什么，不预设新增状态机或界面：

- **资源完整性**：所需文件和入口是否存在，版本是否一致。
- **Expert 选择**：本次 Expert 或任务选择了哪个入口及版本。
- **执行环境**：实际工作目录是否具备该 Skill 所需的配置、脚本和依赖。
- **实际执行**：官方入口是否成功激活，并开始用户要求的工作。

这一个案例尚不足以证明所有 Skill 都需要初始化，也不足以确定统一的准备流程。

## 后续可讨论的能力方向

下表由 John 案例引出，均为候选方向。每项列出用户可观察的效果，便于后续决定是否纳入范围。

| 候选方向           | 要回答的产品问题                               | 若纳入范围，期望的可观察效果                                                 |
| ------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| 区分配置与可用状态 | “已经绑定 Skill”具体说明了什么？               | 用户能区分资源已配置、环境未就绪与实际工作已开始                             |
| 明确执行位置       | Skill 依赖应在哪个目录准备？                   | 用户能确定当前任务实际使用的目录，并理解它与关联代码仓库的关系               |
| 解释前置阻塞       | 缺文件、缺初始化、执行失败或范围限制如何区分？ | 用户能看到与本次任务有关的具体原因和下一步处理项                             |
| 处理后继续原工作   | 补齐依赖后如何恢复讨论？                       | 用户能回到原任务继续，并以实际激活结果判断是否恢复；单纯重新派发不被当成修复 |

上述能力由谁检查、何时检查、如何展示，以及哪些动作可自动执行，均待讨论。当前不确定新的页面、控件或交互流程。

## 与既有产品和技能方案的关系

本次讨论应复用既有概念，避免将“管理资源”“准备执行环境”和“从任务中改进方法”混成一个问题。

| 既有对象或方向             | 已有文档中的职责                               | 对本次讨论的约束                                          |
| -------------------------- | ---------------------------------------------- | --------------------------------------------------------- |
| SkillPackage 与 SkillEntry | 保存完整技能资源及固定版本，索引包内入口       | 将包完整性与项目初始化分别讨论                            |
| Expert 选择与任务快照      | 选择入口，并为任务固定版本和配置               | 故障处理不能被默认为更新或替换任务所用的技能版本          |
| Provider 提交回执          | 记录适配器提交的配置及其一致性                 | 回执不能单独证明模型执行了技能或角色初始化                |
| Skill Evolution            | 从已完成 Run 提炼方法，经审核形成 Skill 新版本 | 属于既有长期产品方向；是否纳入本次 Skill 管理范围仍待确认 |

依据见[技能包研发方案](./expert-skill-package-design.md)、[实施与验收记录](./expert-skill-package-implementation.md)及 [Linx 产品设计 V2.0](./linx-product-design-v2.md)。这些材料提供既有设计与历史实施背景，不代表本次新增能力已经实现。

## 下一轮需要确定的问题

| 待决策问题                                                             | 对范围的影响                                               |
| ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| 用户最困扰的是找不到合适 Skill、配置困难、运行不了，还是难以维护更新？ | 决定首个要解决的实际问题，避免仅凭一次故障确定整个产品方向 |
