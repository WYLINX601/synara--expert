# Synara Expert 中心产品方案

日期：2026-10-28。状态：产品方案已通过（2026-10-28）；已合入本地 main 并更新日用应用 0.1.7，见[验收记录](./expert-center-implementation-2026-10-28.md)。

后续设计见[技术改造方案](./expert-center-technical-plan-2026-10-28.md)。

本版按用户“对齐现有 Expert 能力，避免不必要修改”的要求收敛，替代前版五页签与共享工具中心重组建议。原型标注表示能力归属；示例数据、简化界面不代表已验收的真实运行。

源码基线：`2577e5819353e6089cc3f6e118e848f38df04913`。对比依据见[能力对照](./expert-multica-product-capability-comparison-2026-10-28.md)。

## 1. 标注与改动范围

| 标注       | 含义                                             | 范围                                                                                                                                                 |
| ---------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 已有能力   | 当前源码已有，复用现有组件、操作和保存规则       | 专家卡片列表、搜索、使用中/已归档筛选、新建、复制、归档、恢复、删除；能力/设置、Skills、参考资料、MCP 选择；MCP 配置、检查、授权、使用情况及状态管理 |
| 仅调整入口 | 改变现有能力的入口或页面承载，仍需必要的导航接入 | Expert 列表/详情独立访问；旧设置入口导向同一页面                                                                                                     |
| 本次新增   | 当前没有完整的产品入口，需要补齐                 | 从 Expert 详情进入原有新任务并预选专家；按实际 Expert 绑定聚合任务历史                                                                               |

MCP 保留现有设置入口和返回专家路径，不要求新增顶层“外部工具”导航。不重写工具库、授权或执行机制。

## 2. 页面结构

```text
Experts（独立入口：调整）
├─ 专家卡片列表（已有）
└─ 专家详情（独立访问：调整）
   ├─ 能力（已有）
   │  ├─ 行为指令：工作方式、输出要求
   │  ├─ Skills 绑定及原装配兼容入口
   │  ├─ 参考资料
   │  └─ MCP 工具选择 → 现有 MCP 管理
   ├─ 设置（已有）
   │  ├─ 名称、简介、适用任务
   │  └─ 首选 Provider
   ├─ 任务历史（新增聚合）
   └─ 使用此专家（新增衔接入口）

设置 → MCP（保留）
├─ 外部工具：配置 / 授权 / 使用情况（已有）
└─ 应用接入（已有，保持原样）
```

保留当前卡片列表和“能力 / 设置”结构，不增加概览、Skills、工具三个独立页签。列表不表格化，不增加“全部专家”筛选或连接健康汇总。“使用中”沿用当前未归档筛选含义，不代表正在执行任务。

原型侧栏是本轮范围的导航示意，不替换现有任务、项目等主导航。后续用户补充将原有专家团与技能库集中到专家页，见下节；原能力与旧链接保留。

## 3. 现有能力复用规则

| 区域       | 本轮处理                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理操作   | 保留新建、复制、归档、恢复、删除和原确认规则；归档专家继续只读。上版隐藏删除的建议撤回。                                                        |
| 能力与设置 | 原有字段、预览、校验及错误反馈继续复用。参考资料不能因改版遗漏。首选 Provider 保留“不指定”，不新增专家级模型或推理策略。                        |
| 草稿       | 能力/设置共享 Expert 草稿。Skills、参考资料和 MCP 选择先改变草稿，仍需保存专家；不改成每次操作立即写入。复用保存/放弃、离开保护和并发冲突处理。 |
| Skills     | 复用当前技能库、绑定启用状态及原装配切换，不重做技能库或简化生产装配规则。                                                                      |
| MCP 选择   | 保留现有添加/移除与管理入口；复用当前选择器的全部工具模式及旧版权限处理，不暗改授权语义。                                                       |
| MCP 授权   | 在现有授权页完成允许使用、启动失败处理、全部/选定工具及单独保存；不在 Expert 页再做一套高级授权编辑器。                                         |
| MCP 检查   | 沿用显式检查、工具名称、本页面的检查时间与配置版本。当前不持久化检查历史，不承诺持续在线。检查可能启动本地进程，但不调用业务工具。              |
| MCP 管理   | 复用手动配置、显式发现/导入、来源与冲突、版本、停用/退役/删除、引用保护、使用情况及返回专家。应用接入保持原样。                                 |

连接属于同一 Synara 服务实例；来源属于服务端主机，不误称浏览器电脑。凭证继续按当前配置和引用方式处理，不增加通用令牌登录或 OAuth 流程。

## 4. 新增的两项产品能力

**使用此专家：**在详情增加入口，携带 Expert 选择进入原有新任务草稿。已有项目上下文和运行设置可用时直接沿用；只在缺少必要项目上下文时使用原有选择流程，不强制新增确认向导。保护已有草稿，不静默覆盖内容或专家选择。首次发送才执行，预检仍走现有流程。旧任务不在此热换 Expert；原有派生继续能力保持现状。

**任务历史：**增加页签，按任务实际绑定的 Expert 聚合现有任务。展示任务名、项目、实际状态、最近活动、当时 Expert 版本，点击回到原任务。不新建运行日志或成果验收状态，不把回合结束写成任务成功。版本未知、无记录、归档及访问限制如实呈现。

## 5. 保持的生效规则

| 操作                           | 规则                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| Expert 角色配置、MCP 选择/授权 | 新任务使用新配置；旧任务保持原绑定                                             |
| Skill 内容或绑定更新           | 下一次运行使用最新装配；当前运行、审批等待及恢复保持原装配                     |
| 共享连接配置更新               | 后续新绑定使用；旧任务固定原连接版本                                           |
| 从一个 Expert 移除连接         | 影响该 Expert 后续新任务，不等于全局停用                                       |
| 全局停用                       | 阻止全部使用方后续调用；尝试取消在途调用，不保证撤回外部副作用；启用不自动续跑 |
| 退役                           | 同样全局阻断且不可恢复；历史引用保留                                           |
| 删除连接                       | 沿用现有引用保护，不通过删除历史绕过保护                                       |

## 6. 从上一版移出或纠正

- 撤回五页签重组、列表表格化、新工具中心和独立工具目录页。
- 持久检查记录、工具描述展示不纳入本轮；已有本页检查结果保留。
- 撤回第二套高级授权表单及每次启动必经的确认向导。
- 恢复既有参考资料、删除专家、归档只读与统一草稿保存语义。
- OAuth、批量分配、市场、上下文/记忆、协作、自动化和运营分析仍不纳入本轮。

## 7. 产品验收范围

1. 独立 Expert 入口、详情、旧入口及返回路径有效，不出现两套编辑状态。
2. 现有卡片、能力/设置、参考资料、Skills、MCP 选择、管理操作与草稿保护无功能丢失。
3. 使用专家正确预选，保留现有草稿与运行选择，首次发送前不执行，不增加不必要确认。
4. 历史按实际绑定聚合，可回到原任务；当前配置更新不改写历史。
5. MCP、应用接入与专家团等相邻功能沿用当前能力。
6. 原型逐区域标注归属，示例交互不作为生产实现或运行验收证明。

## 9. 专家团与技能库整合补充（2026-10-28）

来源：用户明确要求“专家团的能力也要组合进专家页”，提供智能体/小队列表参考图，随后要求 Skill 页也进入 Expert 页。本补充已获直接实施授权，覆盖初版专家团留在设置中的入口安排。

- 专家页顶部使用“专家 / 专家团 / 技能”三个分类；个人专家仍使用既有卡片、详情及能力/设置/任务历史。
- 专家团使用紧凑列表，显示数量、名称、用途与成员；复用原有搜索、新建、编辑、归档与恢复，协调者指令、成员选择和协作偏好保持原有能力。
- 技能分类直接复用现有技能库整页，保留创建、导入、筛选、排序、详情编辑、批量绑定和来源更新等现有操作，不复制管理界面。
- 旧 Settings Experts 无 expertId 时进入专家团；带 expertId 时进入个人详情；Agent skills 进入技能分类。MCP 返回个人专家的规则保留。
- 分类切换、直接地址导航与浏览器前进后退均沿用各编辑器的保存/放弃/取消保护；不新增团队执行、协作运行或运营能力。

实际实现与检查见[整合验收](./expert-center-organization-2026-10-28.md)。
