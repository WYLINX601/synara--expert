## 2. 交付目标与分期

用户正常使用 Expert 并给出反馈，系统自行提炼和更新能力；下一次独立工作直接受益。用户可以查看成长、纠偏、恢复版本或关闭学习，不需要处理经验队列，也不需要逐条点击采用。

| 阶段                      | 交付内容                                                                          | 估算           | 退出条件                                                         |
| ------------------------- | --------------------------------------------------------------------------------- | -------------- | ---------------------------------------------------------------- |
| 第一阶段：自动 Skill 学习 | 当前任务证据、自动发现／生成／采用、绑定、生效、星图、关闭与固定版本，覆盖 OMP/Pi | 12–18 工程人日 | 不打开进化页也能完成闭环；两端分别验证新任务实际使用、关闭和恢复 |
| 第二阶段：完整学习能力    | 正式 Space Memory、前台学习工具、资料读取增强、规则版本与细粒度撤回               | 8–14 工程人日  | 同一提交边界覆盖前后台；Memory 的归属和规则冻结生效              |
| 第三阶段：可选评测进化    | 同 Harness 的基础版／候选版实验、择优采用和回归                                   | 6–10 工程人日  | 实测包与采用包相同，评价有任务结果依据，无真实业务重复副作用     |

核心两期合计 20–32 工程人日，含可选第三期 26–42 工程人日。沿用原方案的工程量预算，包含受影响测试、OMP/Pi 联调与修正，不是日历承诺。新增 Harness、OMP 大版本升级、全平台安装包认证与复杂整包合并另估。

第一阶段保留自动体验，暂不加入 Space Memory、前台写入工具、跨会话历史检索、Curator、自动低频归档或模型评分平台。资料学习仅使用当前任务已经实际读取并进入证据的内容。普通纠正学习不等待后续评测模块。

## 4. 第一阶段必须共同落地的规则

1. **一条原生执行链。** Expert 学习协调器只持有业务推进记录，原生任务、模型请求、事件消费者、取消与进程恢复继续归宿主。仅复用已注册的无工具提炼用途；模型不能自行声明自动写入权限。
2. **当前任务证据。** 固定 owner、Expert、Project/Space、thread、turn、root Run、snapshot、assembly 和实际 Provider 身份。消息、工具调用、工具结果与验证使用不同引用类型；截断、缺失和未验证必须可表达。学习任务本身不能再次触发学习。
3. **独立进化点串行提交。** 合并同一目标的重复信号，逐项读取最新版本、生成、校验和提交。无新增价值结束为 `no_change`，不制造 Skill、星图节点或通知。
4. **自动采用仍走正式资产服务。** 复用版本检查、持久意图、幂等操作与保存未绑定恢复。允许改进的共享技能首次完整派生为当前 Expert 专属副本，后续更新同一身份；保留所有绑定字段和支持资源。只读限制不能通过新建同义副本绕过，源包和其他 Expert 不变。
5. **关闭有明确提交边界。** 学习任务带固定 epoch；短提交门协调开关、绑定与冻结清单，模型运行不持锁。关闭回执以后，旧 epoch 不能写入或完成迟到绑定，且不取消业务任务。跨数据库与文件存储使用持久意图协调，不声称跨存储事务。
6. **关闭同时固定版本。** 新独立 Run 使用关闭时完整的包、入口、范围和资源引用。已有 Run、审批继续、自动续接和跨 Worker continuation 优先原记录。显式配置修改、恢复或升级通过同一提交门更新相关固定项；未改变的绑定不顺带追随共享源最新版本。
7. **冻结引用参加资源保留。** 固定清单、未完成意图和历史 Run 的包不能被清理。私有工作树沿用既有持久引用、漂移检测与恢复，不覆盖自写输出，不把工作副本漂移报成源包损坏。
8. **自动过程不变成用户待办。** 内部有界重试、冲突重生成和可说明的跳过；前台优先。只对需要用户处理的持续问题聚合提示；采用、绑定、装配和实际效果分别记录，不能把任一回执冒充效果证明。

## 5. 五批实施与退出条件

依赖顺序为 PR1 → PR2 → PR3 → PR4 → PR5。契约稳定后可按文件边界并行准备测试或 UI fixture，共享宿主接缝由一位负责人串行整合。主会话保留需求、架构、授权语义和最终验收；实际执行时再决定是否委派，不自动创建新工作树或聊天。

### PR1：状态、宿主生命周期与关闭边界（3–5 人日）

交付：

- 新增学习状态、当前任务证据、学习周期三类持久数据的仓储契约及加法迁移。状态保存开关、epoch、并发 revision、绑定 Harness 和固定技能引用；周期只关联既有发现、生成、采用与原生执行身份，不复制任务执行状态。
- 将手动提炼和自动协调改为宿主共享服务；启动时协调未终结记录，关闭时释放观察者，不依赖首次 RPC。owner、数据实例及归属不混用。
- 建立可信内部自动调用入口和共用提交门。普通 RPC 保留 owner 鉴权，不能通过客户端传入 `automatic` 或 epoch 获得后台权限。
- 实现关闭、冻结、固定引用保留以及显式修改后的协调；`RunSkillAssemblyStore` 通过窄解析能力读取 latest/frozen。首次自动入口开放前这些能力必须完备。
- 同步架构标准与 [integration-points.json](../workbench/integration-points.json) 的真实接入点。先登记拟实现能力，结果以实际代码和检查覆盖为准。

主要文件：拟新增 `packages/contracts/src/expertLearning.ts`、`experts/evolution/ExpertLearningRepository.ts`、`ExpertLearningService.ts`、`workbench/host/expertLearningHost.ts`、`expertLearningPersistence.ts` 及扩展迁移；修改现有 RPC、运行时装配、Run resolver 和包引用能力。目录均相对对应应用源码，不另建通用运行框架。

退出：没有打开进化页时服务可恢复；owner 隔离、epoch 拒绝、关闭与提交竞争、固定包保护及原手动路径回归通过。迁移在新库／现有数据副本上可重复启动，原迁移内容不变。本批不开放自动模型派发。

### PR2：当前任务证据与触发（2–3 人日）

交付：

- 拟新增 `experts/evolution/LearningEvidence.ts`，从现有持久事件链形成有界快照；准确关联已完成阶段、用户反馈、工具失败／修正／验证、实际已读取资料与固定版本。
- 在原事件裁剪前持久化必要证据和消费位置；明确事件重放、晚到、缺失、截断以及完成边界的处理。不能将证据写入失败静默当作已成功消费；故障恢复也不能阻断正常任务交付。
- 合并当前工作内的相邻信号，稳定去重；学习关闭、Expert 归档、归属改变、不支持 Harness 和学习任务自身不产生可派发周期。
- 工具证据使用独立引用，避免伪造 message ID；保留“任务结束”与“方法成功验证”的区别。自动选择证据，不增加来源选择必填表单。

主要文件：`ProviderRuntimeIngestion.ts` 的薄接缝、学习证据与仓储、既有来源／输出契约及对应测试。无需改造聊天正文或另订阅 Provider 流。

退出：合成事件覆盖重复投递、长输出、裁剪、旧 Run 迟到、跨 Worker 续接、缺失工具结果和不同归属；只有一次周期登记，证据不落入后一个 Run。本批只验证证据和触发登记，暂不派发模型。

### PR3：自动发现—生成—采用与恢复（3–4 人日）

交付：

- 扩展现有 `SkillEvolutionService`、Prompt 和执行注册，协调器自动推进发现、逐点单结果生成、校验与正式采用。手动备选语义保持，自动模式不能循环采用所有 proposals。
- 每次采用后重新读取准确目标；同一 Expert 内的自动提交串行。模型格式错误、版本冲突与短暂执行故障使用有界预算；无价值或不可恢复项记录原因后结束，不生成用户必处理队列。
- 自动新建的专属绑定显式写入 `allowEvolution: true`；已有绑定授权不被总开关批量提升。首次派生保留完整资源，第二次纠正持续更新同一身份。
- 全链路固定同 Harness 和来源模型／实例／账户，复用隔离目录、空工具、空环境技能与上下文的受限会话。确认普通受管 OMP 会话不会另行自动持久学习，不修改全局配置，不把 SDK 升级并入本批。
- 派发前持久登记；未知发送结果先核对原任务身份，不能盲目补发。采用意图、保存未绑定、关闭中晚到结果和重启均能恢复到真实状态；仅绑定完成的变化进入成长投影。

退出：不开页面也能从合成工作完成自动提交；重复事件／重启不重复派发或采用。覆盖备选拒绝、多个进化点串行、第二次纠正、保存未绑定和关闭竞争。PR1 的固定版本解析与引用保护必须一并可用，才允许本批进入可用候选。

### PR4：自学习开关、成长展示与草稿保护（1–2 人日）

交付：

- 在既有 Expert 编辑弹窗与进化页复用自学习开关、轻量状态、时间线／星图、差异和恢复。普通使用不进入来源选择、候选选择或采用步骤；手动聚焦学习保留为辅助入口。
- 展示已保存且已绑定的能力变化及来源，未实际验证的变化不宣称效果提升；无变化不播报。后台任务沿用原生记录，在需要时从详情查看，不抢占当前聊天或把普通列表塞满学习会话。
- 复用现有 `DetailTabs`、`SettingsEditorDialog`、保存栏、开关、提示和 disclosure 组件；保持设置为默认页，遵循现有响应式布局和用户字体。
- 服务端自动更新 revision 后保留用户未保存草稿和反馈；网络回执不确定时不得覆盖草稿或误显示关闭完成。

退出：受影响 browser 测试覆盖开关、关闭／重开、真实变化、无变化、后台失败、手动流程和自动修订刷新。正式视觉实现前先展示具体局部原型，沿用仓库既有设计确认要求；本次文档归档不等于确认新增视觉布局。

### PR5：OMP/Pi 实跑、故障验证与交付记录（3–4 人日）

交付：

- 使用受管隔离预览、合成材料和用户明确选择的模型／账户，分别完成 OMP 与 Pi 的自动学习和下一独立任务。模型请求实际内容、空工具断言、普通原生自动学习隔离分别记录。
- 模型执行中的取消、运行中重启、提交各阶段中断、关闭后的迟到结果、重开旧任务不复活、共享源更新及固定包清理保护分别验证。
- 完成集中检查，冻结实际受检源码与依赖输入，形成专项验收并同步产品／技术／架构状态和 `PROJECT_CONTEXT`。旧验收数量只作为历史参考。

退出：下表产品闭环和可靠性关键项分别通过，两端真实结果独立记录。不能验证的一端明确保留受限状态，不自动换 Provider，也不把 mock 或目录回执作为实际学习成功。五批全部完成前，不报告第一阶段正式可用；交付先到隔离预览，打包、安装、推送和发布按后续明确授权执行。
