# Obsidian 多库跟随与连接优化

基线：`ae7fb260a`，本轮为工作区修改。用户确认了独立应用上下文设置、自动发现/授权后重连、`@` 上下文 Tab、多库主动绑定、自动跟随与发送快照，并追加每聊天默认 5 个库的可配置上限。架构契约见[架构标准](workbench-adaptation-plan.md)，操作说明见[插件说明](../apps/obsidian-plugin/README.md)。

## 范围与实现

- 应用连接、聊天绑定和消息快照分开；库连接不会自动绑定聊天。同一聊天可主动添加多个库，发送后绑定保留；独立新聊天/派生聊天不继承绑定。
- `@` 文件与上下文分 Tab，方向键切换/选择，Enter 确认，Escape 关闭，输入法组词不接管；文件 Tab 保留一次性文件引用。
- 来源/笔记聚合展示，选区和位置作为内容；正文按本次明确选项过滤，重复内容按语义去重。
- 首次用户批准后按本机实例隔离保存授权；重连不跨实例切换。凭证存于用户专属应用目录，不写入 Vault 或非秘密发现记录；撤销关闭实时源，失败保留可重试状态。
- Markdown 编辑和阅读模式分别采集；阅读模式仅取当前视图内选区，不读取隐藏编辑器旧内容，不编造行号或声称完整正文。
- 每聊天默认上限 5，设置有效范围 1–32；新增与实时捕获同时校验。调低不擅自解绑，超限聊天提示先减少绑定。已冻结的队列/历史消息不重新读取来源。
- 复用原设置父布局、输入框、菜单、附件与 Obsidian 原生设置控件；没有引入独立任务运行时，没有改变 Provider/模型选择。
