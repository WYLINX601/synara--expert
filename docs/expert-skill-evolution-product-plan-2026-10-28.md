# Expert Skill 主动进化产品方案

日期：2026-10-28；执行更新：2026-10-30。状态：已按用户确认推进“发现经验候选→反馈生成草稿→查看差异采用”的两阶段实现；实际检查见[优化验收](./skill-management-optimization-acceptance-2026-10-29.md)，未安装日用。本轮“主动进化”指用户主动发起提炼；不开放会话结束自动触发、定时复盘或自动采用。首轮结果保留在[历史实现验收](./expert-skill-evolution-acceptance-2026-10-29.md)，本轮检查以优化验收为准。

配套：[研发方案](./expert-skill-evolution-technical-plan-2026-10-28.md)、[实施计划](./expert-skill-evolution-implementation-plan-2026-10-28.md)。

## 1. 本轮目标与完成标准

用户以 Expert 为主体发现其工作中值得沉淀的新能力或经验。先查看候选的原因、预期新增方法和证据，再补充反馈生成 Skill 草稿，查看完整差异后采用。入口不预先选择目标 Skill。采用遵循专家绑定上的“允许复制并改进”权限；首次改进共享来源时创建完整专属副本，后续更新该副本；允许无需提炼；当前运行及恢复保留旧装配，下一次独立运行使用新版本。

以专家为经验归集与贡献归属主体，以 Skill 为能力产物；专家不产生 Memory。提炼来源、审批、版本和派生记录是审计数据，不自动注入后续普通会话。

本轮完成标准：一条真实专家工作记录可以产生可追溯候选；用户能正确采用或拒绝；另一次运行能装配采用后的版本；原共享内容、其他专家和当前运行均保留，改进只进入已授权专家的专属版本。

## 2. 保守范围

| 本轮包含                                           | 后续范围                                 |
| -------------------------------------------------- | ---------------------------------------- |
| 用户点击提炼；选择同一专家的一到多段已结束工作记录 | 会话结束、纠错信号、空闲或定时自动触发   |
| 先发现经验候选，补充反馈后生成 Skill 草稿          | 模型直接修改正式 Skill、无人确认自动采用 |
| 每条专家绑定的复制改进权限，缺省关闭               | 自动合并技能、自动归档、自动扩大权限     |
| 首次派生、专用版本更新、新建专用 Skill             | 模型权重训练、系统提示和工具定义的进化   |
| 候选差异、采用、拒绝、失败恢复、恢复旧内容         | 公开市场、远程发布、星图分享码           |
| Expert 内的时间环星图、版本记录和来源查看          | 新建独立学习中心或全量重做专家页面       |
| 系统记录共享原版、专属归属与派生来源               | 专家扩大共享范围或跨专家读取未选材料     |

本期所有模型产物先停在候选，用户“采用”完成一次明确写入。允许复制改进是针对某一专家绑定的长期许可，不包含自动采用；无需再次增加一轮泛化确认。

## 4. 专家绑定权限与技能归属

每条 ExpertSkillBinding 增加可选 allowEvolution；缺省或 false 表示仅使用，true 表示允许复制并改进。它独立于 enabled：暂停使用保留绑定和改进权限；新绑定默认关闭。权限由用户保存在专家绑定中，不从原始 Skill 声明、旧全局策略或模型输出推断。

| 设置                       | 提炼及采用行为                                                           |
| -------------------------- | ------------------------------------------------------------------------ |
| 关闭                       | 可发现与其相关的经验候选；生成其改进草稿和采用前必须先开启权限           |
| 开启且目标为共享原版       | 生成候选不复制；首次采用时复制完整包，应用变更，并仅替换当前专家对应绑定 |
| 开启且目标为本专家专属版本 | 继续更新同一身份；已有副本可复用，不反复复制                             |

原共享版本和其他专家不随该专家改进而改变。整包范围、资源方式、启用状态和改进权限在替换与恢复绑定时保留。共享或专属归属由创建和派生流程记录，技能详情仅展示；移除技能详情的“进化策略”页签和三档全局策略。

从工作记录创建全新技能仍可使用：采用时创建当前专家专属技能，新绑定的改进权限仍缺省关闭。共享技能库的原版继续由用户在技能库直接编辑。已有技能的复制改进权限在生成派发、采用及实际持久写入前重新检查，撤销后旧候选或未决意图不能继续修改技能。

## 5. 主流程与 UI

### 5.1 入口

- 专家详情的任务历史：选择来源后进入同一经验发现流程。
- 专家详情的进化页签：点击“提炼经验”，默认提供近期尚未处理的可用来源，范围可调整。
- 两个入口打开同一流程，不创建两套提炼状态；不在普通聊天输入区新增强制步骤。

专家已归档时保留只读记录，不能发起或采用。原有专家编辑草稿需要先按现有保存／放弃／取消规则处理；提炼使用已保存配置，不隐式保存其他草稿。

### 5.2 发现经验候选

进化入口先显示专家和可分析的工作片段范围，不要求选择某一个 Skill。默认使用近期已结束且尚未完成发现的片段，一次至多 5 段；范围和模型沿用既有控件收在可展开设置中。自动默认值不构成未保存草稿，用户修改来源或重点后沿用现有离开保护。没有来源时简洁显示“暂无可提炼的工作经验”，不展示一长串不可操作表单。

只读取该专家实际参与且用户提交的明确回合，固定消息边界，不静默扫描全部历史或外部资料。发现阶段只提供现有绑定技能的名称、描述等目录信息，用于识别重复和建议落点；不读取技能文件、不复制包、不改变技能或绑定，也不产生已学会能力事件。结束不代表成果已验证，经验仍需准确来源证据。

一次返回 0–3 条经验候选。每条包含名称、为什么值得沉淀、准备增加的方法、来源证据；可以建议一个来自该专家目录的现有技能，也可建议新方法。模型不能授予复制权限、指定归属或输出文件。没有新经验和证据不足都是正常结果。

### 5.3 反馈、生成草稿与采用

| 阶段     | 用户看到什么                             | 明确动作与结果                                                   |
| -------- | ---------------------------------------- | ---------------------------------------------------------------- |
| 经验候选 | 名称、原因、预期新增方法、证据           | 可补充反馈，点“生成 Skill”或“忽略”                               |
| 生成草稿 | 基于候选与反馈形成的完整文件和差异       | 用户可以编辑、拒绝或采用；不会自动保存正式技能                   |
| 采用     | 具体目标、完整文件列表、支持文件和删改项 | 新方法创建专属 Skill；已有方法首次建立专属副本，后续复用同一身份 |

生成阶段沿用发现阶段选定的账户与模型、冻结来源和经验候选摘要，不另选模型或静默切换 Provider。对现有目标重新读取当前版本与已保存绑定权限；未开启复制权限时提供返回“能力”的既有入口，不悄悄改成新建来规避权限。用户此时尚未审阅文件差异，所以生成可基于当前保存版本；采用继续绑定准确基础包、专家修订与摘要。

反馈生成是独立且可取消的原生任务，有独立持久请求和准确 thread/turn 身份。相同 ID 与载荷返回同一次结果；未知网络结果重试不重复派发。完成草稿后再次生成需要具体反馈，新的生成轮次使旧草稿不可采用。失败或已确认取消后可明确重试，不要求编造新反馈；采用中或已采用时不能重新生成覆盖已有结果。

经验候选可忽略，记录仍保留；有执行中、采用中或已采用的子任务时不能关闭。候选和未采用草稿不点亮星图。当前存在的三类采用按钮继续按实际 action 表示新建专属技能、首次派生或更新专属版本，不增加第二轮泛化确认。

模型输出无效时在同一阶段最多修正一次。分析失败与证据不足分开；关闭面板不等于取消。每个阶段均提供既有任务链接和准确取消入口。首次采用后绑定变更仍经版本 CAS；冲突保留草稿并要求基于新状态生成，不自动覆盖或未经复审合并。

### 5.4 部分完成与恢复

独立副本保存后、专家绑定前失败：明确显示“专用 Skill 已保存，尚未绑定”，提供继续绑定和查看 Skill；重试复用同一副本，不重复创建。只有绑定完成才标为已采用并记录能力变化。

恢复旧内容仅针对当前已绑定且允许改进的本专家专属版本，先预览差异；恢复会生成一个新的修订，不改写历史，不修改当前运行。首次独立采用的撤销涉及恢复原绑定时，必须显示具体绑定变化；不自动删除已被引用的副本。

## 6. 星图与版本记录

沿用 Hermes 的时间环布局、平移缩放、时间轴播放／暂停、节点选择和详情。专家通过页面标题与数据范围体现，不再设置一个巨大的专家中心节点。

- 一个 Skill 身份一个节点；版本放在节点详情和进化记录中，不因每次修改制造新节点。
- 首次派生画有方向的来源关系；明确关联可另行表示，不能把相似度连线当作血缘。
- 已绑定／已装配的共享来源可作为基线节点，不计为新学会能力；没有真实调用证据时不写“已使用”，节点大小固定，不编造能力分数。
- 时间轴基于实际采用事件；旧数据缺少创建时间时标为“基线／时间未知”，不从更新时间猜学习时间。
- 时间回溯展示当时已记录的节点和版本；无历史证据的时期不补造过去事件。
- 节点显示共享／专属、版本、派生来源与贡献专家；点击查看现有技能详情及选定版本差异。
- 无需提炼、被拒绝、失败及候选未采用只在记录中出现，不点亮新能力。
- 首期不提供星图分享码，不把图分享与 Skill 开放混为一项操作。

## 7. 不变的运行规则

Skill 内容或绑定更新从下一次独立运行生效；当前运行、审批等待、自动续接及恢复使用原装配。专家角色和 MCP 配置继续遵守原快照规则。内容保存、装配成功、模型实际采用与业务效果验证是不同状态，不互相代替。

## 8. 产品验收

1. 两个入口使用同一流程，只读取所选专家、所选材料，不影响普通聊天。
2. 用户开始前不运行模型，候选采用前不改变正式 Skill 或绑定；拒绝和无需提炼不写正式 Skill、修订或绑定，保留必要审计记录。
3. 发现只读目录且不需要复制权限；生成已有技能改进与采用必须获许可，撤销后派发和重启重放不能写入。
4. 两阶段请求、来源、反馈、父子关系与准确摘要可追溯；每次正式写入需要查看差异并采用，忽略或过期草稿不能写入。
5. 首次派生一次，保留完整原版和绑定字段；其他专家不变，后续更新同一专属身份。
6. 重复提交、断线和重启不重复启动、重复创建或重复绑定；部分完成如实呈现。
7. 当前／恢复／自动续接装配不变，下一次独立运行可验证装配新版本。
8. 星图、记录、版本和来源一致，键盘、缩放、字体、减少动画、窄屏及真实父布局可用。
9. 专家不生成 Memory；提炼任务不递归作为新经验来源，不自动开放或执行生成脚本。
10. 真实模型验证与平台验证按实际结果记录；本方案和原型不作为完成证明。
