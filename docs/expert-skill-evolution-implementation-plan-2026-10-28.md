# Expert Skill 主动进化实施计划

日期：2026-10-28；执行更新：2026-10-30。状态：A–E 首轮实现保留在[历史验收](./expert-skill-evolution-acceptance-2026-10-29.md)；当前专家经验发现、反馈生成与采用两阶段流程已实施，本轮检查、真实 Provider／平台范围和交付边界见[优化验收](./skill-management-optimization-acceptance-2026-10-29.md)。“主动”指用户点击提炼，未启用自动采用。

权威范围：[产品方案](./expert-skill-evolution-product-plan-2026-10-28.md)。接口与数据：[研发方案](./expert-skill-evolution-technical-plan-2026-10-28.md)。本文件只维护实施顺序、依赖和验收，不复制架构。

## 1. 实施原则

- 先完成手动闭环，再完成星图；后台自动触发、自动采用不进入本轮。
- 主会话保留需求、架构与验收；只有接口明确后分派独立执行。只读源码和候选原型不代表功能完成。
- 复用现有受管预览；实施前核对其负责人、差异、固定源码、数据版本、进程和容量，不因分工创建多份环境。
- 每阶段聚焦检查，最后合并一次完整门禁；日用数据库和应用在开发期不变。

## 4. 核心验收场景

本轮先验证发现→反馈→生成→采用：经验候选不读文件或写正式 Skill，准确证据／目录 ID／摘要不能伪造；生成继承父模型和冻结消息，重新核验权限；父子原生任务、取消和重启不重复；反馈新轮次拒绝旧草稿；失败或取消后可显式重试；采用前原版、绑定与星图不变。以下原有采用场景继续保留。

| 编号  | 场景                         | 必须证明                                                                                                          |
| ----- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| EV-01 | 绑定改进权限缺省关闭         | 缺省及 false 不派发目标改进；只有 true 可生成，模型伪造权限不能写入                                               |
| EV-02 | 两个专家绑定同一原版         | 权限分别配置；一人改进产生专属副本，原版、另一人和当前 Run 不变                                                   |
| EV-03 | 产品经理独立进化             | 首次一份产品 Driven，源 Driven 不变；保持 enabled／allowEvolution／selectionScope／resourceMode，后续只增专用修订 |
| EV-04 | 反复点击、断线、重启         | 模型任务、Skill 身份、绑定及采用事件均不重复                                                                      |
| EV-05 | 副本保存后绑定失败           | 如实显示 saved_unbound；继续绑定不重建副本；冲突不覆盖用户新配置                                                  |
| EV-06 | 无需提炼／证据不足／模型失败 | 三种结果可区分；无正式 Skill、版本及星图能力写入                                                                  |
| EV-07 | 并发专属更新与权限撤销       | 过期候选冲突；权限撤销后不能采用或重放，不能后写覆盖或未经复审自动合并                                            |
| EV-08 | 当前与后续运行               | 审批等待、恢复、自动续接保持装配；同一会话下一独立 Run 更新                                                       |
| EV-09 | 历史与回退                   | 来源和旧包可读；恢复产生新修订；历史不重写，当前运行不热换                                                        |
| EV-10 | 原版重新绑定后再次改进       | 复用既有专属副本，不重复创建；仅替换当前绑定并保留其全部字段                                                      |
| EV-11 | 来源与隔离                   | 只读取选中身份和截止片段；提炼任务不递归学习；专家不生成 Memory                                                   |
| EV-12 | UI 整合                      | 原专家／专家团／技能能力不丢失；未保存草稿、前后导航、键盘、缩放、字体、减少动画和窄屏有效                        |

## 5. 检查和交付

迭代期执行所改模块的 Vitest 与浏览器场景。E 阶段集中执行仓库要求的格式、lint、typecheck、受影响与全库测试、workbench 边界、迁移归属；平台／进程边界有改动才增加对应检查。真实 Provider 至少覆盖支持入口的实际执行、取消、权限等待和新旧包装配，不能以生成 JSON 或 catalog 收据代替模型采用。

交付材料包含：固定源码、实际检查、Provider／平台状态矩阵、产品演示、已知缺口及恢复入口。若用户后续授权合入、推送或更新日用，另冻结候选并走既有交付 SOP；本轮方案不提前执行。

## 6. 风险与退出路径

- 原生 Provider 无法兑现提炼约束：阶段 A 阻止开放该 Provider，不扩大权限；可继续完成与之无关的采用／UI 工作。
- Skill 与绑定跨存储：明确分阶段恢复，不承诺原子事务；保存未绑定需要用户可见出口。
- 专业经验影响共享方法：专家改进统一写入专属副本，原版由用户在技能库维护。
- Skill 数量膨胀：优先查重、更新现有专用版；无新增内容正常结束。
- 来源过大或无验收证据：限制所选范围并展示未知项，不把模型总结当作事实。
- 历史包被清理：待审基础包和采用事件引用必须进入保留检查；未完成前不关闭恢复验收。

环境收尾：方案阶段仅创建原型。2026-10-29 实施复用既有 Expert 预览工作树，独立 home/端口运行应用与 Pi 验收模型；不改日用数据。实际实例、检查与收尾见实现验收。
