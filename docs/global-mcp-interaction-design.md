# 全局 MCP 管理交互方案：借鉴 CC Switch

> 2026-10-04 实施安排更新：用户已批准精简现有交互原型。本轮更新原型的信息组织与交互，不扩展到正式应用；原型使用示例数据，不接真实 API。
> 状态：交互设计提案，尚未实现。日期：2026-10-04。

目标：让用户先找到和配置 MCP 服务，再决定哪些专家可以使用哪些工具。沿用[技术架构](./global-mcp-management-architecture.md)的实例目录、独立授权与任务绑定规则，使用 Synara 原生风格。

## 1. 本轮实际参考了什么

### 1.1 界面观察

本轮通过界面工具查看了用户电脑上正在运行的 CC Switch，并取得以下页面截图与界面文本：

- MCP 管理列表：页头新增/导入入口，数量汇总，搜索框，服务行，各应用启用按钮。
- 新增 MCP 全屏面板：预设入口、标识与显示名称、应用选择、折叠附加信息、JSON 配置区。
- 配置向导：stdio/HTTP 类型切换后动态改变字段；stdio 显示命令、参数和环境变量，HTTP 显示 URL 与请求头。

仅打开新增界面和向导、切换未保存的类型，然后取消并返回原列表。没有新增服务、保存配置、改变应用开关、导入或删除。观察结束时服务数量与应用开关仍与进入前一致。

本机运行版本未单独核对；实际界面观察与下述固定版本源码证据分别记录，不能将两者视为同一版本的完整验收。官方手册图片在线访问失败，因此本轮的视觉依据是本机真实界面截图，而不是未打开的网页图片。

## 2. 借鉴关系与适配

| CC Switch 的组织方式       | Synara 的交互设计                                        | 适配原因                                                  |
| -------------------------- | -------------------------------------------------------- | --------------------------------------------------------- |
| 一个页面集中管理服务       | 设置 → MCP → 外部工具，以服务列表为首页                  | 共享连接集中维护，减少从专家详情逐个找配置                |
| 数量汇总与搜索位于列表上方 | 只显示搜索结果数量；搜索名称、ID、命令/主机摘要          | 避免重复统计；凭证、请求头值、环境变量值不进入搜索        |
| 使用方开关紧邻服务         | 列表显示“已授权 N 位专家”，点击进入该连接的专家授权      | 专家数量动态增长，不把所有专家开关横向铺在每一行          |
| 新增/编辑使用专门面板      | 在 Synara 设置内容区进入独立编辑视图，返回时保留列表位置 | 字段较多，沿用专家页列表到详情的模式                      |
| JSON 编辑区附带配置向导    | 默认使用现有结构化表单；高级区域提供脱敏配置预览         | 普通配置不要求用户先写 JSON，也避免表单与 JSON 草稿不一致 |
| 可选信息折叠展示           | 优先显示连接所需字段，其余已有字段收进高级配置           | 降低首次配置负担；未支持的描述/标签字段不先造 UI          |
| 顶部导入入口               | 有真实导入服务后提供“来源 → 条目 → 差异 → 确认”          | 处理同名、格式和凭证转换，保留已有配置                    |

采用 Synara 的 `SettingsPanelPrimitives`、输入、按钮、Switch、Menu、Dialog、Tooltip 与现有主题。字号使用 `text-ui*`；折叠使用既有 disclosure 动效和 reduced-motion。开关与状态包含文字标签，编辑操作可以通过键盘访问。

## 3. 信息层级

### 3.1 MCP 设置入口

顶层仅保留两个分区：

| 分区     | 内容                                                |
| -------- | --------------------------------------------------- |
| 外部工具 | 外部 MCP 服务目录，连接配置，按专家授权，引用与影响 |
| 应用接入 | 现有原生 MCP connections 的配对与项目/任务访问范围  |

进入“外部工具”默认显示服务列表。侧栏只保留 MCP 主入口，两个分类只在页内标签出现。专家页的“工具权限”或“选择工具”入口定位到相应连接和当前专家，返回时恢复专家详情；存在草稿时先处理未保存提示。

原型只保留一条全局说明：“交互演示 · 不连接真实服务，刷新后重置”。字段标签、勾选、开关和列标题已表达的信息，不再逐行复述。实现方式放入文档；操作后果与异常原因保留在对应操作旁。

### 3.2 服务列表

从上到下：页头标题 → 分类标签 → 搜索、结果数量、筛选与“添加连接” → 服务行。CLI 导入在 MCP-3 可用后再显示，首期不放不可用的按钮。

首期列表只展示实际已有数据。搜索基础字段；筛选“全部 / 已被专家授权 / 未授权”。全局停用功能随 MCP-1 提供后，再增加相应状态筛选。

| 服务行区域 | 显示内容 / 操作                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 连接       | 显示名称可点击进入配置，次级显示 stdio/HTTP 类型；ID、命令和主机在配置详情中展示                                         |
| 全局状态   | 已启用 / 已停用 / 已退役，与授权和检查独立                                                                               |
| 授权专家   | “N 位”，进入授权视图；数量指专家开关开启且白名单非空的配置，包含全局停用后保留的授权，不能当作当前可用或正在运行的任务数 |
| 最近检查   | 未检查 / 检查通过 / 检查失败 / 结果已过期，附配置版本与检查时间                                                          |

四个共享列标题替代逐行重复标签；窄屏以就地标签保持对应关系。名称已是详情入口，不再添加同义的“查看详情”按钮。停用、退役和删除在连接详情中操作。

停用状态、最近检查与专家授权是三个独立信息：连接检查通过不代表专家已获授权；某位专家开关开启也不代表连接可用。

列表不逐行自动建连。检查状态不从开关或保存成功推断，不增加模拟检查。

### 3.3 连接详情

详情标题显示服务名称、配置版本和返回列表入口。内部三个视图：

| 视图       | 内容                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------ |
| 连接配置   | 结构化配置表单、高级配置预览、保存与真实检查                                                     |
| 工具与授权 | 专家、允许使用、允许的工具与已选数量、启动时无法连接的处理策略；工具名称以功能名为主、协议名为次 |
| 使用情况   | 合为一组分类明细：专家引用、任务绑定、运行会话；数量不再另做重复统计                             |

连接配置和专家授权分别保存，操作栏明确显示“保存连接”或“保存专家授权”。切换视图保留草稿；离开、换连接或换专家复用未保存提示。

工具发现失败时仍可保留和维护已有工具名称。旧发现结果显示所属版本；新版本不会借用旧结果冒充本次发现。

## 4. 主要操作流程

### 4.1 添加连接

1. 在列表点击“添加连接”，进入独立编辑视图。
2. 填写名称与 ID。新建时只显示配置表单，校验唯一 ID，保存后 ID 只读，避免引用失效。
3. 选择当前实现支持的 stdio 或 HTTP，显示相应字段。
4. stdio 填命令、参数及服务端环境变量引用；HTTP 填 URL、请求头名称、环境变量引用和可选前缀。
5. 点击“保存连接”，成功后显示配置版本及授权入口；新连接没有专家授权。检查和其他详情标签在首次保存后出现。
6. 可选点击“检查连接并读取工具”，实际建连并展示本次结果。该动作可能启动本地服务进程，界面直接说明。
7. 进入“工具与授权”，选择专家、配置白名单并保存授权。

新增连接默认不绑定专家。保存连接不启动任务，不勾选全部工具，不自动配置独立 CLI。模板目录待真实模板及维护机制确定后再引入，不复制参考产品的示例列表。

### 4.2 编辑连接

点击行上的编辑 → 改配置 → 保存新 revision → 原检查结果标为过期。页内用一句话说明：新任务使用新版本，已绑定任务及恢复仍使用保存的版本；这一说明仅在 MCP-1 的版本绑定已实现后成立。

MCP-0 单独交付时，界面需说明当前任务恢复仍可能读取最新连接配置，不能提前展示尚未成立的保障。

### 4.3 专家授权

从专家详情进入时默认选中该专家；从服务列表进入时先选择专家。工具清单按当前配置版本的发现结果与已保存白名单合并展示。

| 情况                   | 操作行为                                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 首次允许，无白名单     | 专家页显示“选择工具”，进入该专家的授权草稿；选择至少一个工具并保存后才生效。草稿可开启允许使用，但零工具时就地提示并禁止保存 |
| 开启已有授权           | 恢复原白名单，不添加新发现工具                                                                                               |
| 关闭专家开关           | 保存后影响后续新任务；保留白名单供再次启用                                                                                   |
| 修改白名单或必需项     | 保存该专家的新 revision；冲突保留草稿并显示服务端版本                                                                        |
| 要立即阻止全部任务使用 | 使用连接的全局停用操作，与专家开关分开说明                                                                                   |

授权页用复选框表达每项选择，标题旁显示“已选 N / M”，不再逐项写“已选 / 未选”或添加重复授权摘要。关闭允许使用时置灰工具与必需项，保留已有选择；“新增工具默认不授权”只在工具区说明一次。“必需连接”的文案直接表达启动时连接失败会阻止任务启动，不能让用户误认为每次工具调用失败都会中止任务。

专家页正常行显示工具数量、专家开关和工具权限入口；全局停用或退役时显示明确原因与查看连接入口，保留的授权不能表现为当前可用。应用接入统一展示客户端、配对状态、访问范围和管理操作，配对及范围字段仅为演示数据，不模拟凭证或真实配对成功。

首期保持逐专家编辑，不提供“一键授权全部专家/全部工具”。授权数量较多时通过搜索专家与筛选已授权对象定位。关闭授权后保留工具的专家仍构成配置引用，使用情况中标明“已关闭，保留工具”；列表授权人数不包含这些关闭项，删除保护仍包含这些引用。

### 4.4 停用、退役与删除（MCP-1）

更多菜单按当前服务状态显示操作。停用前展示受影响专家、任务与正在运行的会话；确认后阻止后续调用，并反馈在途调用取消/关闭的实际结果。它属于运行操作，不与普通保存混在一起。

有引用时展示停用/退役；硬删除不可用并说明引用来源。无引用时删除才进入确认。停用后的工具即使仍出现在某个 Provider 的缓存里，调用也必须由服务端拒绝，界面不承担权限执行。

### 4.5 导入已有配置（MCP-3）

入口集中在列表页头，借鉴 CC Switch 的可发现性，流程按 Synara 的冲突与凭证规则调整：

1. 选择已支持的来源，显示服务端主机与读取路径。
2. 展示扫描结果及解析问题，用户选择条目。
3. 对每项显示新增、相同、冲突、不可转换；同 ID 冲突可选跳过、更新现有或另建 ID，更新需 expectedRevision。
4. 明文密钥引导映射为环境变量引用；不把密钥写进预览、日志和专家授权。
5. 显示最终变化，用户确认后应用，逐项反馈结果。

导入服务定义不会自动授予专家，也不会反向同步外部应用。独立 CLI 同步另设入口和差异确认，不与 Synara 内授权共用一个开关。

## 5. 草稿、错误与状态

| 场景                    | 界面反馈                                                  |
| ----------------------- | --------------------------------------------------------- |
| 列表加载中              | 使用 Synara 原有加载状态                                  |
| 目录为空                | 说明尚无连接，提供添加入口                                |
| 搜索无结果              | 显示无匹配结果及清除筛选，不误报目录为空                  |
| 读取失败                | 就地错误与重试入口，不显示成空目录                        |
| 保存中                  | 当前操作 pending，防止重复保存与重复切换                  |
| 保存冲突                | 草稿保留，展示最新 revision，提供重新载入或重新编辑       |
| 保存失败                | 错误放在操作区，字段内容保留；成功 toast 不能覆盖失败结果 |
| 检查中 / 失败           | 显示真实进度或错误；取消与结束释放检查会话资源            |
| 切换连接/专家或离开页面 | 保存 / 放弃 / 取消离开，复用既有草稿保护                  |

MCP 设置的外部工具页与应用接入页切换同样遵守草稿保护。键盘焦点、屏幕阅读器名称、窄屏操作入口与用户字号变化纳入实现验收。

## 6. 与技术实施阶段对应

| 阶段          | 本方案交付的交互                                                                 |
| ------------- | -------------------------------------------------------------------------------- |
| MCP-0         | 统一入口、服务列表与搜索、独立结构化编辑、连接级专家授权、真实检查结果和草稿保护 |
| MCP-1         | 任务绑定版本展示、引用与影响、全局停用/退役以及准确的更新说明                    |
| MCP-2（待定） | 普通任务选择；不因 UI 对照提前开放                                               |
| MCP-3（可选） | 来源选择、导入预览、差异处理、独立 CLI 同步                                      |

本轮更新[可点击原型](./prototypes/global-mcp-v1/README.md)与本方案，不修改 Synara 正式应用。原型浏览器检查与正式前端、后端验收分别记录。

## 7. 最小交互验收场景

- 搜索服务 → 编辑 → 返回，搜索和列表位置保留。
- 新增连接 → 保存 → 明确真实检查 → 选择专家与工具 → 保存授权，无自动授权副作用。
- 关闭专家开关后再开启，原白名单保留。
- 保存连接新版本，旧检查结果标为过期。
- 改配置或授权后换页，草稿提示能取消离开。
- 全局停用有引用的连接，显示影响并验证服务端拒绝后续调用。
- 后续导入遇重名和不可转换字段，用户能预览处理，不静默覆盖。

以上是后续实现的验收要求，不是本轮已完成的应用测试。
