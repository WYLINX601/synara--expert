## 建议的简洁交付结构

沿用现有目录和已确认的保留规则，不为整理而搬迁或改名：

```text
唯一交付根 /
  installation-receipt.json    当前安装了什么
  current-recovery.json        当前可用的上一版配套恢复入口
  candidate/                   本次产物及验收；最多一个待验候选
  recovery-set/                恢复应用、数据库和配置
  application/asset-backups/   与数据快照配对的工作区及 profile
  history/                     必要的历史回执、摘要和失败证据
```

`candidate/` 目前也保留已安装的 0.1.13 包和证据，目录名本身不表示有待验候选。开始新候选前先按现行轮换规则核对已有内容。安装状态以回执、实际应用和对应证据为准，不能从目录名称推断。

| 内容                     | 处理原则                                                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 源码、方案与正式验收文档 | 由 Git 管理；未提交源码、未跟踪文件和独有现场先保全，不能假定已经入库。                                                                      |
| 本次安装包与恢复组合     | 留当前安装产物、上一版兼容应用与配套数据；另外最多一个待验候选。普通环境备份保留最近两份已验证完整组合；被引用或固定的历史／迁移点额外保留。 |
| 临时解压、构建和测试缓存 | 任务结束后核实归属、可重建性与占用，再删除；下次运行可重新生成。                                                                             |
| 历史材料                 | 保留必要版本、来源、哈希、回执和失败证据；不再为每次 AI 任务复制整套应用、依赖或用户目录。历史用户数据和固定恢复点不能由源码替代。           |
| 待核查材料               | 不按日期、目录名、分支已合入或文件体积判断可删除；登记路径、原因和继续条件。                                                                 |

每次交付只需四步：① 盘点现有根、容量、运行进程和恢复入口；② 在根内准备本次候选并验证对应源码、产物与成套备份；③ 更新并回读当前安装／恢复入口；④ 核验后回收被替代的临时文件，报告保留项、删除项、空间变化和受阻项。无安装的普通开发只记录相应源码和验证状态，不重复制作完整安装包。

当前没有统一的自动盘点、跨任务互斥或全量自动轮换工具。后续如果实现工具，应先提供只读分类和明确目标，再逐项核验路径、占用、恢复引用与替代组合；任何不确定项停止相关删除。现有局部备份轮换不代表这些能力已经实现。
